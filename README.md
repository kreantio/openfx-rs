# OpenFX bindings and tools for Rust

> [!NOTE]
>
> As of 2026/11/14, the pinned commit for the `vendor/openfx-data` submodule is
> the latest commit of
> [`kreantio/openfx-data#7`](https://github.com/kreantio/openfx-data/pull/7)
> rather than a commit on the main line. This is because the ongoing development
> requires the changes from that PR, but the PR is further blocked by an
> external upstream PR not having been merged into its main branch.
>
> Although I'd like to keep all submodules in this repository on their main
> lines, as is the case for `openfx-data`, this situation hinders the
> development process of this project. Considering this, I decided to loosen
> this “rule”.

## Prerequisites

The following tools are required:

| Tool(s) \\ To                           | Use crate `openfx` | Build Examples           | Update Generated Code in Crate `openfx` |
| --------------------------------------- | ------------------ | ------------------------ | --------------------------------------- |
| The [Rust] programming language         | `stable`           | `nightly-2026-10-10`[^1] | `stable`                                |
| POSIX tools (`sh`, `rm`, `mkdir`, etc.) | no                 | yes                      | not strictly                            |
| [`just`]                                | no                 | not strictly             | not strictly                            |

[Rust]: https://rust-lang.org/
[`just`]: https://github.com/casey/just

[^1]: Only because
    [`cargo build --artifact-dir` is unstable](https://github.com/rust-lang/cargo/issues/6790).

## Internal Crates

| Name                       | Published? | Description                                           |
| -------------------------- | ---------- | ----------------------------------------------------- |
| [`openfx-internal-macros`] | Yes        | internal procedural macros for the crate `openfx`     |

## Subprojects

- openfx-datagen: https://github.com/kreantio/openfx-datagen
  - a tool for generating data from the official OpenFX C headers
- openfx-data: https://github.com/kreantio/openfx-data
  - stores data generated by openfx-datagen
